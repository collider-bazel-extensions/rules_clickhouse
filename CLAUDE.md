# rules_clickhouse

Bazel rules for a hermetic per-test ClickHouse server:
- `clickhouse_schema`: ordered migrations;
- `clickhouse_server` + `clickhouse_health_check`: the server, alone or as a rules_itest service;
- `clickhouse_test`: an `sh_test` macro with `ch` helpers.

It mirrors rules_valkey's structure (launcher, trampoline, control endpoint), rules_pg's migrations and rules_argocd's version pins; see DESIGN.md.

## Commit requirements

- All tests must pass before any commit with code changes: `bazel test //tests/...`. Run `.github/consumer/check.sh <scratch dir>` too when the extension, `MODULE.bazel`, `.gitattributes` or the public API changes.
- All documentation (`README.md`, `DESIGN.md`, `CLAUDE.md`) must be updated to reflect any code changes before committing: new rules, changed attributes, new public API surface, behaviour changes.
- The `CLICKHOUSE_*` variable names are a stable interface (rules_openmeter consumes them). Add new ones; don't rename or remove.
- Every commit message ends with a blank line and `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Key concepts

- **One binary.** `clickhouse` is multi-call: `clickhouse server`, `clickhouse client`. It is about 840 MB unpacked. Spawning it costs about 0.3 s, so readiness polls `/ping` over HTTP rather than running the client.
- **Generated config.** `config.xml` names every path under the state dir and only the HTTP and native listeners on 127.0.0.1. `config`/`users` fragments are staged with owned elements removed (`_FORCED` in launcher.py = `FORCED_SETTINGS` in server.bzl; keep them in sync). Merge-time `replace`/`remove` doesn't work for repeated elements such as `listen_host`.
- **Server env.** cwd/HOME/TMPDIR = state dir, no `CLICKHOUSE_*` from the caller, `CLICKHOUSE_WATCHDOG_ENABLE=0`, own session (`SYSTEM SHUTDOWN` signals its process group).
- **Errors.** `explain()` shows `<Error>`/`<Fatal>`/`Exception` lines without stack frames from the error log and stdout.log (early errors go to stdout). Migration failures name the file, the line (found from the client's `(query: …)`), the statement and the error.
- **Ports.** Two free ports with `listen_try=0`; "Address already in use" means a retry with new ports. A restart binds the same ports, with 5 × 0.2 s retries.

## Public API

```python
load("@rules_clickhouse//:defs.bzl",
    "clickhouse_schema",        # srcs
    "clickhouse_server",        # schema, seed, database, password, config, users, ready_timeout, extra_args
    "clickhouse_health_check",  # server
    "clickhouse_test",          # srcs + clickhouse_server attrs + args, env, data, deps, ...
    "ClickHouseBinaryInfo", "ClickHouseSchemaInfo", "ClickHouseServerInfo",
)
```

Env: `CLICKHOUSE_HOST HTTP_PORT NATIVE_PORT NATIVE_ADDR DATABASE USER PASSWORD HTTP_URL DSN VERSION BIN CLIENT_CONFIG STATE_DIR LOG ERROR_LOG CONTROL_URL` (+ `TESTLIB` in clickhouse_test).

## Development

```sh
bazel test //tests/...
.github/consumer/check.sh /tmp/claude-1004/rc-consumer
tools/update_versions.sh 26.9.32.8 26.10.6.18   # regenerate pins (downloads ~1.6 GB)
tools/update_versions.sh --check                # checksum files only
```

Don't `bazel build //...`: it fetches every platform's binary. Use the target paths in CI's build step.

To find stray servers, use `pgrep -x clickhouse` (an exact process name). Never use `pkill -f` with a pattern: it matches the shell running it.

### Test results (last full run: 2026-11-18)

All 34 test targets in `//tests/...` pass on Linux x86_64 (ClickHouse 26.9.32.8), 14 of them analysis tests. `parallel_test` runs 4 shards.
- 5 runs each of 9 server tests in parallel (45 runs; `parallel_test`: 20 shard runs) passed with no stray servers. Startup under that load was 2.0–4.7 s (median 3.5 s), on a machine with a load average of about 60.
- Alone, the server is ready in 1.0–1.3 s, and the env file appears 2.0–2.5 s after launch with 3 migrations.
- A `/tmp` and runfiles probe file made `isolation_test` fail, as it should.

## Known limitations

- `python3` is required on the host.
- macOS and linux_arm64 are pinned and their downloads verified, but not run here.
- No TLS listeners, no Keeper or replicated tables, and no clusters.
- `storage_configuration` disk paths in fragments are not rewritten.
- `clickhouse_test` wraps `sh_test`; other languages use `clickhouse_server` through rules_itest.
